# 04 · M1 数据与组织模型

> 状态：组织模型已与使用者确认（2026-09-16），本文档是 M1 实现的设计底座。

## 1. 已确认决策

| 决策点 | 结论 |
|---|---|
| Vault 模式 | **单 vault + 文件夹分区**（存储布局天然兼容将来加多 vault，见 §5） |
| 侧栏功能 | **最近笔记 + 收藏**（在笔记本树之外常驻显示） |
| 文件名规范 | **规范化为 kebab 风格**：只允许 `a-z 0-9 -`，空格/下划线 → `-`，其他非法字符剔除 |

## 2. 文件名生成规则（细节与默认选择）

- 允许字符集：`[a-z0-9-]`（扩展名 `.md` 除外）
- 变换：空格与 `_` → `-`；连续 `-` 合并；首尾 `-` 去除；大写转小写
- **中文标题不进文件名**（按你的选择），此时文件名回退为 `YYYY-MM-DD-<6位id>`（如 `2026-09-16-k3f9q2.md`）
- **标题存储**：写入笔记 frontmatter 的 `title:`；显示名优先级 = frontmatter title > 文件名去扩展名

```
---
title: 我的读书笔记
---
# 我的读书笔记
…
```

已知的取舍：Obsidian 里显示的是文件名（`2026-09-16-k3f9q2`），不是 frontmatter title——这是此方案的代价。如果实际用起来别扭，改成「拼音 slug」（`wo-de-du-shu-bi-ji.md`）或「保留中文文件名」都只是改一个生成函数，不影响数据与同步协议。

## 3. 笔记身份与侧栏

- **笔记身份**：路径即身份（M1）；重命名 = 原子 rename + DB 联动更新（M3 同步协议将引入稳定 id，路径变化不影响同步）
- **最近笔记**：`.lanmark/` DB 表 `recents(path, opened_at)`，打开即记录，上限 50 条
- **收藏**：表 `favorites(path, added_at)`；侧栏拖拽或星标切换；重命名联动

## 4. Vault 布局（重申 + 细化）

```
<vault>/                      ← 单 vault 根目录（App 配置 vaultPath 指向）
├── <文件夹>/…/*.md           ← 目录即层级，无虚拟目录
├── assets/                   ← 附件：内容 sha256 前 16 位命名（a3f8….png），相对路径引用
└── .lanmark/
    ├── config.json           # vaultPath 所属设备信息（M2 扩展）
    ├── lanmark.db            # SQLite：files 索引 + FTS5(recents/favorites)
    └── trash/                # 回收站（删除永不硬删，铁律）
```

## 5. 多 vault 的预留方式

App 全局配置（`~/.config/lanmark/` 或等价位置）当前只存一个 `vaultPath`。将来支持多 vault 时：配置升级为 vault 列表 + UI 库切换器，每个 vault 目录自带 `.lanmark/` 元数据，**数据零迁移、同步协议零改动**（手机端按 vault 目录粒度多跑一份同步状态即可）。

## 6. 对 M1 任务清单的影响

1. Vault 选择（首次启动选目录 → 写入全局配置）
2. 目录树 CRUD（建/删/重命名文件夹与笔记，rename 走联动）
3. 文件名规范化函数 + frontmatter title 写入/读取
4. Milkdown 编辑器 + 源码模式（决策门不变）
5. SQLite：files 索引、FTS5 搜索、recents、favorites
6. 图片粘贴/拖入 → assets/ + 相对引用插入
7. 侧栏：笔记本树 + 最近 + 收藏三段式
