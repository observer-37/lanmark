# M2：移动端对齐 + 手机同步服务器

> 状态：设计稿（M1 验收通过后启动）。协议与冲突策略沿用 docs/02 已确认决策：
> 文件级版本对比、冲突保留双份、TLS+证书固定推迟到 M4。

## 1. 目标

1. Android 端功能对齐 M1（打开/创建 vault、目录树 CRUD、编辑器、搜索、最近/收藏、图片）
2. 手机作为局域网同步中心节点：App 内嵌 axum 服务器，桌面端连接后双向同步
3. 配对与发现：mDNS 广播 + 扫码获取地址

**非目标（M3/M4）**：文件监听（notify）、增量块级同步、TLS、断点续传、多 vault。

## 2. 架构

```
┌─ 手机（中心节点）────────────────┐      ┌─ 桌面/其它端 ──────────┐
│ Lanmark App                       │      │ Lanmark App            │
│  ├ 本地 vault（app 文档目录/SAF）  │      │  ├ 本地 vault          │
│  ├ 同步引擎（TS 或 Rust）          │      │  ├ 同步客户端          │
│  └ axum 服务器（:4180）  ◄────────┼──────►│  └ mDNS 发现 + 扫码    │
│      mDNS 广播 _lanmark._tcp      │ LAN   │                       │
└───────────────────────────────────┘      └───────────────────────┘
```

- 服务器**随 App 启动而启动**（前台服务保活，权限 `specialUse`），监听 `0.0.0.0:4180`
- 同步引擎放 **Rust 侧**（复用 M1 的 `_op` 命令层：note_read/write、hash、reindex——零新数据通路）；axum 为 M2 新增依赖（Android 交叉编译在 M2a 首日验证）

## 3. 同步协议（v1，JSON over HTTP）

每文件版本 = `sha256`（M1 的 `files.hash`）+ `mtime_ms`（`files.mtime_ms`）。无中央版本号，幂等设计。

| 端点 | 方法 | 语义 |
|---|---|---|
| `/api/v1/info` | GET | 服务器名、vault 统计、配对状态 |
| `/api/v1/pair` | POST | 提交配对码 → 返回 token（M4 前 token 仅防误连，不加密） |
| `/api/v1/manifest` | GET | `[{path, hash, mtime_ms, size, kind}]`（全量清单） |
| `/api/v1/pull` | POST | `{paths: [...]}` → 逐文件 `{content_base64, hash, mtime_ms}`（仅推对方 hash 不同的） |
| `/api/v1/push` | POST | 同 pull 反向：客户端把本地更新推给服务器 |
| `/api/v1/delete` | POST | `{paths: [...]}`（软删：服务器入回收站） |

**一次同步回合**（幂等、可重放）：

1. 客户端拉 manifest，与本地 `files` 表对比，分四类：
   - 仅服务器有 → 拉取落盘（`write_note` 原子写 + 更新索引）
   - 仅本地有 → 推送
   - 两边 hash 相同 → 跳过
   - **两边 hash 不同（冲突）→ 保留双份**：服务器版本下载为 `<stem>-冲突<mmdd-HHMM>.md`，本地版本原样保留后推送（服务器侧对同名再走一次冲突命名）
2. 删除同步：对方清单里没有而本地回收站能对上 hash 的文件，按软删传播（M2 简化：不自动传删除，只同步增改；删除传播放 M3）

**图片/附件**：`assets/` 下文件同样走 hash 对比（`kind=asset`，manifest 全量覆盖）；拉取按 sha16 文件名幂等落盘。

**并发保护**：服务器写文件一律 tmp+rename（M1 已有）；同一回合内单写者（客户端串行同步，锁在 TS 侧）。

## 4. 发现与配对

- 手机端：`mDNS` 广播 `_lanmark._tcp`（端口 4180，TXT 含设备名）；UI 显示当前配对码（8 位，首次生成后持久化）
- 桌面端「添加同步服务器」：mDNS 浏览列表（`mdns-sd` crate / JS 侧 `bonjour-service`）→ 选择 → 输入配对码 → `/pair` 拿 token → 保存
- **扫码兜底**（mDNS 跨网段失效时）：手机 UI 显示二维码 `lanmark://sync?host=192.168.x.x:4180&code=ABC12345`；桌面端相机扫码（M2 用「手输/粘贴 URL」替代相机，相机扫码放 M3）

## 5. Android 专项

| 项 | 方案 | 风险 |
|---|---|---|
| vault 选择 | SAF `ACTION_OPEN_DOCUMENT_TREE`（自研小插件，M1 已留 `vault_set_path` 接口） | 中：持久 URI 权限 |
| 服务器保活 | 前台服务（`specialUse` 权限）+ 通知栏常驻「Lanmark 同步中」 | **高：Android 13+ 后台限制**，M2 首要真机验证项 |
| 编辑器 | 复用 Web 前端（WebView），M1 的 IME 结论直接适用 | 低 |
| 端口占用/冲突 | 4180 被占时 +1 重试，mDNS TXT 上报实际端口 | 低 |

## 6. 里程碑拆分

- **M2a 真机对齐**：SAF vault 选择 + M1 功能 Android 走查 + 前台服务骨架（服务器先占位）
- **M2b 同步服务器**：axum 端点 + manifest/pull/push + 冲突双份 + 手机 UI（同步状态/配对码）
- **M2c 桌面客户端**：mDNS 发现 + 同步触发（手动按钮，自动周期放 M3）+ 端到端验证

## 7. 验收标准（M2）

1. 真机：Android 打开 vault → 建目录/写图文/搜索全流程可走通
2. 局域网：桌面端发现手机、配对成功；双向各建 1 篇笔记，两端同步回合后互见
3. 冲突：两端离线各改同一文件 → 同步后双份都在、无丢失
4. 断网重连：拔网线 5 分钟恢复，同步回合幂等收敛
5. Rust/前端测试全绿；CI 三端绿
