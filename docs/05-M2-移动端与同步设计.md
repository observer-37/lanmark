## 1. 目标

1. Android 端功能对齐 M1（打开/创建 vault、目录树 CRUD、编辑器、搜索、最近/收藏、图片）
2. 手机作为局域网同步中心节点：App 内嵌 axum 服务器，桌面端连接后双向同步
3. 配对与发现：mDNS 广播 + 扫码获取地址

**非目标（M3/M4）**：文件监听（notify）、增量块级同步、TLS、断点续传、多 vault。

## 2. 架构

```
┌─ 手机（中心节点）────────────────┐      ┌─ 桌面/其它端 ──────────┐
│ Lanmark App                       │      │ Lanmark App            │
│  ├ 本地 vault（app 文档目录/SAF）  │      │  ├ 本地 vault          │
│  ├ 同步引擎（TS 或 Rust）          │      │  ├ 同步客户端          │
│  └ axum 服务器（:4180）  ◄────────┼──────►│  └ mDNS 发现 + 扫码    │
│      mDNS 广播 _lanmark._tcp      │ LAN   │                       │
└───────────────────────────────────┘      └───────────────────────┘
```

- 服务器**随 App 启动而启动**（前台服务保活，权限 `specialUse`），监听 `0.0.0.0:4180`
- 同步引擎放 **Rust 侧**（复用 M1 的 `_op` 命令层：note_read/write、hash、reindex——零新数据通路）；axum 为 M2 新增依赖（Android 交叉编译在 M2a 首日验证）

## 3. 同步协议（v1，JSON over HTTP）

每文件版本 = `sha256`（M1 的 `files.hash`）+ `mtime_ms`（`files.mtime_ms`）。无中央版本号，幂等设计。

| 端点 | 方法 | 语义 |
|---|---|---|
| `/api/v1/info` | GET | 服务器名、vault 统计、配对状态 |
| `/api/v1/pair` | POST | 提交配对码 → 返回 token（M4 前 token 仅防误连，不加密） |
| `/api/v1/manifest` | GET | `[{path, hash, mtime_ms, size, kind}]`（全量清单） |
| `/api/v1/pull` | POST | `{paths: [...]}` → 逐文件 `{content_base64, hash, mtime_ms}`（仅推对方 hash 不同的） |
| `/api/v1/push` | POST | 同 pull 反向：客户端把本地更新推给服务器 |
| `/api/v1/delete` | POST | `{paths: [...]}`（软删：服务器入回收站） |

**一次同步回合**（幂等、可重放）：

1. 客户端拉 manifest，与本地 `files` 表对比，分四类：
   - 仅服务器有 → 拉取落盘（`write_note` 原子写 + 更新索引）
   - 仅本地有 → 推送
   - 两边 hash 相同 → 跳过
   - **两边 hash 不同（冲突）→ 保留双份**：服务器版本下载为 `<stem>-冲突<mmdd-HHMM>.md`，本地版本原样保留后推送（服务器侧对同名再走一次冲突命名）
2. 删除同步：对方清单里没有而本地回收站能对上 hash 的文件，按软删传播（M2 简化：不自动传删除，只同步增改；删除传播放 M3）

**图片/附件**：`assets/` 下文件同样走 hash 对比（`kind=asset`，manifest 全量覆盖）；拉取按 sha16 文件名幂等落盘。

**并发保护**：服务器写文件一律 tmp+rename（M1 已有）；同一回合内单写者（客户端串行同步，锁在 TS 侧）。

## 4. 发现与配对

- 手机端：`mDNS` 广播 `_lanmark._tcp`（端口 4180，TXT 含设备名）；UI 显示当前配对码（8 位，首次生成后持久化）
- 桌面端「添加同步服务器」：mDNS 浏览列表（`mdns-sd` crate / JS 侧 `bonjour-service`）→ 选择 → 输入配对码 → `/pair` 拿 token → 保存
- **扫码兜底**（mDNS 跨网段失效时）：手机 UI 显示二维码 `lanmark://sync?host=192.168.x.x:4180&code=ABC12345`；桌面端相机扫码（M2 用「手输/粘贴 URL」替代相机，相机扫码放 M3）

### 8b. 同步回合（实现语义，docs/05 §3 的细化）

1. 客户端拉服务器 manifest（notes+assets 全量，`{path, kind, hash, mtimeMs, size}`）
2. 与本地清单 + **基线**（上轮结束时服务器 hash 快照）对比分类：
   - 仅服务器有 → 拉取（`write_note` 原子写+索引 / `save_asset` 内容寻址幂等）
   - 仅本地有 → 推送
   - hash 相同 → 跳过
   - hash 不同且**本地 hash == 基线** → 只有服务器改过 → **快进拉取**（不产生冲突副本）
   - hash 不同且**服务器 hash == 基线** → 只有本地改过 → 直接推送
   - 两者皆非（双方都改过，或无基线如首次同步）→ **冲突保留双份**：服务器版本落本地 `<stem>-冲突<mmdd-HHMM>.md`（进索引），本地版本原样保留后以服务器当前 hash 为 base 推送
3. 推送请求带 `baseHash`（客户端所见服务器旧版）：服务器现 hash ≠ baseHash（竞态）→ 服务器侧也走冲突命名后再落盘；内容 sha256 校验不符拒收
4. 回合结束把「服务器现值」写回基线（.lanmark/sync-<id>.json，不参与同步）
5. 删除传播 M2 不做（/api/v1/delete 端点已备，M3 接）

**实现差异说明**：设计稿 §3 的纯 hash 四分类会把「只有一方改过」也判成冲突（例如手机离线改了一篇、桌面没动过 → 桌面拉 manifest 后发现 hash 不同 → 误判冲突，笔记分裂成两个文件）。基线是「文件级版本对比」的最小完备化：三方对比（服务器现值 / 本地现值 / 上轮服务器值）才能区分快进与冲突。已实测覆盖：快进、双向各改不同文件、双方改同一文件、推送竞态四个场景（`sync_client.rs` 集成测试）。

### 8c. 配对与发现（实现）

- 手机端配对码 8 位数字，首次生成持久化 `.lanmark/sync.json`；token = sha256(码+时间+pid) hex，签发即持久化（服务器重启后桌面 token 仍有效）
- 桌面「自动发现」= mdns-sd browse 2s；mDNS 失败（网段隔离/多播被丢）时手输 `http://ip:4180` 是对等路径（设计稿 §4 的扫码兜底在 M2 同样以手输呈现）
- 服务器 4180..4189 逐个试绑，UI 显示实际端口

### 8d. Android 保活（关键决策，详见 docs/06）

- **上滑划掉 Activity 会 `process::exit(0)` 连前台服务一起杀**（tauri#15671）→ `RunEvent::ExitRequested` + `api.prevent_exit()`（仅 Android cfg；桌面正常退出）；划掉后重开白屏（wry 不给新 Activity 建 webview）→ `RunEvent::Resumed` 时 `webview_windows().is_empty()` 则重建窗口
- FGS 类型 specialUse：manifest 声明 + `PROPERTY_SPECIAL_USE_FGS_SUBTYPE` + API 34+ `ServiceCompat.startForeground` 显式传类型
- MulticastLock 随 SyncService 生命周期持有（Android 13 前 mDNS 收包必需；mdns-sd 需含 PR #469 修复的版本，0.21.3 已含）
- WifiLock 无效（调研结论），熄屏保活靠 FGS（网络无限制）+ 引导用户把电池策略设为「不受限」（验收清单项）
- vault 打开即启动服务器（`open_vault_at` 末尾 cfg(android) 分支，幂等）；进程被杀重建后随自动开库复活

### 8e. vault 目录选择（Android，决策记录）

- **SAF+路径映射在 targetSdk 30+ 不可写**（调研核心结论）：SAF 树授权只给 content:// 通道，映射回的 /storage 路径 std::fs 直写 EACCES
- **方案：MANAGE_EXTERNAL_STORAGE + 既有 `vault_set_path` 路径接口零改动**（侧载分发无 Play 政策顾虑）；SAF 选择器仅作目录选择 UI，primary 卷确定性映射（`primary:rel` → `/storage/emulated/0/rel`，syncthing-android 同款）
- 保留「应用目录」免授权回退（M1 行为）；v1 只承诺内部存储（primary 卷）
- 本地功能验证：授权流程/真机选目录 → 真机验收清单

**验收中发现并修复（6 项，均有回归测试或真机复验）**：

1. **小屏布局不可用**：侧栏 288px 挤占编辑器 → 窄屏（<768px）抽屉式侧栏 + 悬浮 ☰；targetSdk 35+ **系统强制 edge-to-edge**，删 `enableEdgeToEdge` 无效，须在 MainActivity 对 decorView 做 insets 避让（`setOnApplyWindowInsetsListener` + systemBars padding）
2. **推送不建父目录**：对端目录树为空时 `write_note` 报 ENOENT → push/pull 两侧 `create_dir_all` 父目录
3. **附件按内容寻址改名**：非 sha 命名附件（Obsidian/演示库）推送被拒 → 附件按**原路径**落盘（内容 hash 校验保留）
4. **manifest hash 与磁盘脱节**：DB 缓存 hash 过时导致拉取校验必挂 → 清单以磁盘字节为准 + 同步回合前 reindex + pull 服务实际字节 hash
5. **非 UTF-8 笔记字节污染**：`from_utf8_lossy` 破坏 GBK 等外来文件 → 新增 `write_note_bytes` 字节级保真（索引 body 仍 lossy 供搜索）
6. **划掉重开白屏（tauri#15671）**：FGS 保活下 activity 重建，新窗口拿不到绑定（tao 日志：旧窗口 Destroyed、新窗口 WindowId(0)）；`is_empty()` 判据失效（注册表残留旧句柄）→ 改为 **ExitRequested 置 ACTIVITY_LOST 标志 + 下次 Resumed 销毁旧窗口并重建**（普通切后台不经过 ExitRequested，无副作用）

**已知限制（不阻塞验收）**：

- **mDNS 发现在本机桌面 WiFi 环境不可达**：手机 daemon 正常（logcat 证实收包/注册），桌面发出的多播查询帧未到手机（其他设备间多播互通，疑桌面 WiFi 驱动多播发送问题）。手输 URL 为设计内对等路径，已验证。热点环境复测待做
