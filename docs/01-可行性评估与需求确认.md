# 01 · 可行性评估与需求确认

> 项目代号：**Lanmark**（LAN + mark，局域网 markdown 笔记）
> 状态：需求已确认（见 §4），技术选型见《02-技术选型与工程路线》

---

## 1. 总体结论

**可行。** 三个特性中没有"做不到"的部分，核心风险集中在 **Android 后台常驻服务受系统限制**，其余为成熟技术组合。

## 2. 分项评估

### 2.1 多端（Windows / Linux / Android）—— 风险低

| 方案 | Windows | Linux | Android | 备注 |
|---|---|---|---|---|
| Flutter | ✅ stable | ✅ stable | ✅ 最佳 | 单语言 Dart；桌面文本输入/IME 需调校 |
| Tauri 2 + Web 前端 | ✅ | ✅ | ✅（2.0 起稳定） | 2024-10 发布稳定版，移动端 DX 略逊桌面，部分官方插件不支持移动端 |
| Compose Multiplatform (Kotlin) | ✅ | ✅ | ✅ 一等公民 | 桌面 JVM 打包体积大；markdown 编辑器需自研 |

真正的风险不在平台覆盖，而在**编辑器组件**（详见 2.2）。

### 2.2 Markdown 编辑 —— 风险低（选对编辑器的前提下）

- 格式本身零风险；工作量集中在编辑体验：中文 IME、快捷键、选区、粘贴图片。
- **所见即所得（Typora 风格）是编辑器要求最高的形态**，Web 系（ProseMirror 生态：Milkdown/TipTap）是唯一成熟路线；Flutter 生态（AppFlowy Editor 等） fidelity 不足；Compose 生态基本空白。

### 2.3 局域网同步 + 手机当服务器 —— 可行，核心风险点

**先例**：Syncthing（Android 常驻服务 + LAN 同步）、LocalSend（手机/桌面局域网互传）。

**已确认满足的技术要点**：
- Android App 进程内跑 HTTP 服务：Rust `axum`（Tauri core 进程内）可行
- 设备发现：mDNS（Android `NsdManager` / Rust `mdns-sd`）+ 扫码配对
- 安全：配对 token；Android 9+ 默认禁明文 HTTP，需 networkSecurityConfig 或自签 TLS
- 前台服务：社区插件 `tauri-plugin-background-service` 提供 Android 前台服务 + START_STICKY 自动重启 + 开机恢复 + Android 15 超时恢复策略

**必须接受的平台限制**：
1. **前台服务常驻通知绕不开**（Android 8+ 后台执行限制，平台设计如此）
2. **Android 15 对 `dataSync` 类型前台服务有 6 小时/24 小时运行上限**（用户切回前台会重置）；对策：`specialUse` 类型（自用侧载无商店审核问题）
3. **国产 ROM 杀后台激进**（MIUI/HyperOS、EMUI、ColorOS）：需引导页请求电池白名单 + 自启动权限
4. **Doze 深度休眠断网**：partial wake lock + 白名单缓解，耗电略增
5. **使用模型**：手机不在局域网时其他设备失去中心节点——白天在电脑写的笔记，回家连上后才同步。这是"随身服务器"模型的固有属性

## 3. 设计改进（相对原始设想）

| # | 改进 | 理由 |
|---|---|---|
| 1 | 同步用"文件级版本比对 + 冲突保留两份"，不上 CRDT | 单人多设备场景 CRDT 无必要，复杂度数倍；协议留演进空间 |
| 2 | 纯 `.md` 文件目录 + SQLite 索引 | 数据不被锁死，Obsidian/VSCode 可直接打开；同步协议简单 |
| 3 | MVP 手机为中心，协议按"任意端可为中心"设计 | 后续演进去中心化不用推倒 |
| 4 | 扫码配对（QR 含 IP:port:token）+ mDNS 自动发现 | 比手输 IP 好一个量级 |
| 5 | 文件级 hash 差量传输 | 单用户量级足够，不引入分块去重 |
| 6 | **铁律：同步引擎永不静默删数据**——删除先进回收站，冲突必留底 | 同步出 bug 的后果是数据丢失，此条为最高设计约束 |

## 4. 已确认需求（交互式确认结果）

| 维度 | 决定 |
|---|---|
| 使用者背景 | 无既定技术栈，由选型按项目需求决定 |
| 跨端方案 | 由选型推荐（结果：Tauri 2，见 02 文档） |
| 存储 | Markdown 文件目录 + SQLite 索引 |
| 同步语义 | 文件级版本比对 + 冲突保留两份副本 |
| 编辑器 | **所见即所得（Typora 风格）** |
| 服务器角色 | MVP 手机为中心；协议预留"任意端可为中心" |
| MVP 功能范围 | 文件夹/笔记本层级、全文搜索、图片/附件 |
| 明确排除（一期） | 标签/双链、回收站+历史版本、导出 PDF/HTML（回收站因"铁律"仍需最小实现） |
