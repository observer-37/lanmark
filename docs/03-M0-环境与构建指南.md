# 03 · M0 环境与构建指南

> M0 目标：三端贯通——桌面可开发调试、Android APK 可装到手机、前后端双向桥接验证、CI 产出构建物。

## 1. 环境总览

| 组件 | 位置 | 说明 |
|---|---|---|
| Node 26 / pnpm 11 | 系统 | 包管理 |
| Rust（系统级 1.98） | `/usr/bin/cargo` | 桌面端编译 |
| rustup + stable（含 4 个 Android target） | `.cache/rustup` + `.cache/cargo` | Android 交叉编译 |
| Temurin JDK 21 | `.cache/jdk/` | Gradle 8.14 不支持本机 JDK 26 |
| Android SDK（platform-tools / android-34 + 36 / build-tools 34.0.0） | `.cache/android-sdk/` | curl 手工组装（见 §5 坑表） |
| Android NDK r27d | `.cache/android-sdk/ndk/27.3.13750724` | 同上 |
| Gradle 缓存 | `.cache/gradle/` | 避免写 `~/.gradle` |

**约定**：所有构建前先 `source scripts/env.sh`——它把 RUSTUP_HOME/CARGO_HOME/JAVA_HOME/ANDROID_HOME/NDK_HOME/GRADLE_USER_HOME 指到仓库内 `.cache/`（已 gitignore）。

## 2. 日常开发（桌面）

```bash
pnpm install
pnpm tauri dev        # 热重载开发窗口
```

只调 UI 时可 `pnpm dev` 用浏览器看界面（Rust 命令不可用，App 会显示「web 模式」并优雅报错）。

Rust 侧：

```bash
cd src-tauri && cargo check && cargo test   # 或 source ../scripts/env.sh 后在根目录执行
```

## 3. Android 构建（本机）

```bash
source scripts/env.sh
pnpm tauri android init          # 生成 src-tauri/gen/android（首次；之后提交到 git）
pnpm tauri android build --apk --target aarch64
# 产物：src-tauri/gen/android/app/build/outputs/apk/universalRelease/*.apk
adb install <apk>                # 或直接把 APK 传到手机安装
```

真机调试（热重载）：手机开 USB 调试后 `adb devices` 确认，然后

```bash
pnpm tauri android dev
```

## 4. CI

`.github/workflows/build.yml`：push 到 main 自动构建三端（Windows NSIS/MSI、Linux deb/AppImage、Android APK aarch64），产物在 Actions Artifacts 下载。

## 5. 已知坑与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| `cargo` 报无法写 `~/.cargo` | 沙箱限制 `$HOME` 写入 | `source scripts/env.sh` 重定向到 `.cache/cargo` |
| **sdkmanager 报 IO exception（manifest 拉不下来）** | 本网络下 Java 直连 dl.google.com 被重置（curl 正常，Java 被掐） | 已绕过：SDK 用 curl 手工组装（repo.xml 查文件名 → zip → 解压标准布局 → 手写 licenses） |
| **Gradle 拉不到 google maven** | 同上 | `.cache/gradle/init.d/mirrors.gradle` 全局重定向到阿里云镜像；gradle 分发包走腾讯镜像（gen/android/gradle-wrapper.properties） |
| **AGP 报 AndroidLocationsException（多个 android 目录变量）** | 同时设了 `ANDROID_USER_HOME` 和已弃用的 `ANDROID_SDK_HOME`（语义不同：后者是其下的 `.android` 父目录） | 只设 `ANDROID_USER_HOME`（env.sh 已如此） |
| **AGP 崩溃 / 只读文件系统 `~/.android`** | 沙箱 `$HOME` 只读 | 同上，已重定向到 `.cache/android-user-home` |
| 改了 env 变量但 gradle 行为没变 | gradle daemon 缓存了旧环境 | `cd src-tauri/gen/android && ./gradlew --stop` |
| AGP 默认要 build-tools 35.0.0 | 本网络无法自动下载 | `app/build.gradle.kts` 已钉 `buildToolsVersion = "34.0.0"` |
| Gradle 报 unsupported class file | 用了系统 JDK 26 | 确认已 source `scripts/env.sh`（JAVA_HOME 指向 JDK 21） |
| `tauri android build` 找不到 NDK | NDK_HOME 未解析 | source env.sh 后 `echo $NDK_HOME` 检查 |
| **AppImage 空白窗口后 WebKitWebProcess SIGABRT**（journal: `Could not create default EGL display: EGL_BAD_PARAMETER`） | AppImage 捆绑的 Ubuntu 24.04 Mesa/EGL 无法初始化较新的 GPU（本机 Intel Arc Arrow Lake-P 实测触发）；`WEBKIT_DISABLE_DMABUF_RENDERER` / `WEBKIT_DISABLE_COMPOSITING_MODE` / `LIBGL_ALWAYS_SOFTWARE` 均无效 | **用本机原生构建**：`scripts/lanmark-desktop.sh`（链接系统 webkit/Mesa，与宿主驱动匹配，实测正常）。AppImage 兼容性改进列入 M4（候选：不用 AppImage、或捆绑更新 Mesa、或按需软件渲染） |
| AppImage 打包失败（本机） | 需要 FUSE 等 | 本机验证用 `pnpm tauri build --no-bundle`，完整打包交给 CI |
